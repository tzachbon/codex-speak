### 2026-10-21 Windows (T4 safety contract proposal)

- Fresh planning review found blockers in the original T4 design: app/window/text cannot identify a field or caret, existing clipboard restore is unchecked and races with other borrowers, UIA characters and keyboard steps are not UTF-16 units, and selection collapse is not proof of a successful paste. - Proposed additive cross-platform call contract: `replace(text, ctx=None)`, `type_at_caret(text, ctx=None)`, `select_back(n, ctx=None)`. Shared Writer must pass its captured context for every asynchronous mutation. No mutable last-capture global. Context retains the five public fields and adds Windows-private primitive field runtime ID and exact selection/caret offsets. Capture preserves whitespace and refuses multiple selections. Undo must precheck the verified post-paste target before selecting any span, then capture the selected inserted span afresh before replacing it with the original.
- Windows T4 implementation plan: all UIA calls run on one MTA worker, returning primitive snapshots only, with no retained COM ranges outside their apartment. Inspect password/security metadata and terminal class before any text read or synthetic key. Compare process, window, field identity, selection/caret endpoints, and exact text again immediately before input. For fields without verifiable endpoints, refuse automatic mutation and offer Copy. Use ValuePattern.IsReadOnly or the range IsReadOnly attribute as affirmative writable evidence. Candidate undo range is inspected and measured in UTF-16 before selecting it, never Shift+Left multiplied by UTF-16 length.
- Clipboard fixes stay within Windows ownership: checked pointer-sized native bindings, valid hidden owner HWND, checked complete snapshots, preallocate transferable data before clearing, and conditional restoration with the sequence check inside the acquired clipboard lock. A shared Windows borrower lock serializes reading selection copies and Writer pastes. Selection copy fallback must verify the clipboard owner belongs to the captured process, recheck the target, and skip restore on concurrent change. Unsupported formats or failed snapshot/allocation refuse borrowing. Restore failures are reported, never silently treated as success.
- Paste completion uses bounded polling for the exact inserted span and resulting caret at the captured location, not a fixed sleep or merely changed selection. Refuse held modifiers, use a balanced SendInput batch, check event count, never elevate. `True` means verified insertion. `False` after input may mean an unconfirmed side effect, so the shared caller must offer Copy without automatic retry. Global focus changes and another app's clipboard consumption cannot be made atomic, so unverifiable targets fail closed.
